# 複数ファイルを追うコードレビューでの比較

## 差分と比較条件

合成差分を4件使った。各差分に13～14個の補足資料があり、本番の設定・依存先・分岐・利用側のコードを照合する。旧版、開発用や別経路の実装も含めた。コード品質とセキュリティの各観点に、実際に問題がある差分と、関連する問題が対策済みの対照を1件ずつ用意した。

| 観点 | 問題がある差分 | 対照 |
| --- | --- | --- |
| コード品質 | 本番ワーカーが保存を予約しただけで準備完了と報告する | 保存と準備完了の更新を、予約された処理の中で順番に行う |
| セキュリティ | 会員向け明細の取得でアカウントの絞り込みが失われる | Web アダプターで認証済みアカウントに絞る |

両方の観点に、表面的には問題に見える別の変更も含めた。再利用判定は未完了のジョブを返すように見えるが、現行の検索結果に未完了は含まれない。活動記録は入力の全項目を書き込むように見えるが、会員用の実装は保存前に項目を絞る。

GPT-6 Luna（medium）、同じ Markdown、同じ `focus`、同じ基本のレビュー指示を使用。モデル API を直接利用し、同じ固定資料一式を供給元とした。各方式12試行。合計36件の新規レビューを行い、素の LLM の生応答をそのまま Quick の検証に再生した。さらに、その検証を通った同じ候補を固定し、2種類の独立照合をそれぞれ追加で行った。各モデル呼び出しの出力上限は4,096トークン。Standard と全資料 recheck は既存の2段階の指示・出力形式を使用する。候補と引用を採点し、方式別に集計した。

## 実測結果

| 方式 | 既知問題を検出 | 引用で因果を支持 | 対照で実害を確認できない指摘 | 実行時間の中央値 |
| --- | ---: | ---: | ---: | ---: |
| 素の LLM・全資料 | 6/6 | 6/6 | 3 | 15.9秒 |
| 同じ応答を Quick の位置検証に通す | 6/6 | 6/6 | 3 | 15.9秒 |
| Standard・許可資料を選んで取得 | 6/6 | 4/6 | 3 | 46.1秒 |
| 全資料で recheck | 4/6 | 1/6 | 3 | 24.6秒 |
| 固定候補をまとめて独立照合 | 6/6 | 6/6 | 3 | 26.2秒 |
| 固定候補を変更・経路・影響ごとに独立照合 | 4/6 | 4/6 | 0 | 30.6秒 |

- Quick の位置検証で除外された指摘は0件。対照の3件はいずれも引用位置が有効だった。保存前に呼び出しが戻るという挙動差は確認できるが、呼び出し元が戻りを準備完了として扱う証拠はない。固定資料で定義していたのは、外部状態が準備完了であればアーカイブを取得できるという契約。
- Standard は追加資料を各試行7～8件取得し、2件の既知問題を毎回検出した。引用で実行経路を裏づけられたのは6件中4件で、主な不足は本番のエントリと設定を結ぶ行だった。全試行の入力トークンは約7.8万、素の LLM は約4.1万。Standard と全資料 recheck はそれぞれ12試行中11試行で未解決の調査質問が残った。
- 一括照合では、実害の前提を確認できないと理由欄に書きながら候補を採用した。項目別照合では対照の3件を未確認に回したが、既知の2件も未確認に回した。理由は HTTP の読み取りルートと、明細表示関数の本文がなかったこと。前者は準備完了の契約違反、後者は会員向け表示処理に他アカウントの明細を渡すところまで資料で追える。候補が具体的な外部応答まで主張したことで、その先の資料が必要になった。
- 対照は2種類で、結果は同じ事例の反復。実案件で同じ比率になるかは未確認。項目別照合の結果は候補を確定指摘から保留した数であり、新規候補の発見や書き換えは計測していない。

## Evaluator で管理するもの

モデルは、Markdown で指定された観点の候補を探し、既知の反証や資料を読み取る。Evaluator は同じ候補を固定して照合結果を紐づけ、資料の版と引用位置を検証し、確認できた範囲と未確認の主張を呼び出し元に返す。今回の項目別照合のように候補全体を保留する方式では、確認済みの問題まで失われる。

次の設計案では、根拠が成立した範囲まで主張を縮め、確認できなかった影響と、判断に必要な資料を同じ候補の記録に残す。たとえば「準備完了時にアーカイブが存在しない」は確定候補に残し、具体的な HTTP 応答は対応する経路の資料が揃うまで保留する。意味判断はモデルが担う。Evaluator が固定するのは候補の識別子、版付き資料、主張ごとの判定・引用、確定・保留の遷移。具体的なシナリオ用の分岐は持たない。この案の検出・保留成績は未計測。

製品 API と実行経路は編集していない。固定モデルによる事前照合で、資料選択と取得、Quick の呼び出し回数、素のモデル応答の再生を確認した。`bun run verify` は63件成功。ローカルの `verification-runs/markdown-review-hard.d0bxGc/` に資料・試行・採点を保存した。
