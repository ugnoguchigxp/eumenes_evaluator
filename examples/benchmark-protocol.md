# Luna計測の条件

調整用6件で入力と採点手順を確認し、最終評価用18件を別に使う。各構成をケースごとに3回実行する。最終評価用のケース、既知問題、根拠、期待状態を固定してから実行する。調整と最終評価の指摘は構成名を伏せて採点し、最終判断には人の確認を使う。Codexだけで採点した結果は暫定値とする。

```sh
bun run bench:check
bun run bench run --openai --suite examples/calibration-suite.json --repeat 3
bun run bench run --openai --suite examples/final-suite.json --repeat 3
bun run bench run --openai --suite examples/multi-evidence-suite.json --repeat 3
bun run bench score <run-directory> <scores.json>
```

## 固定する比較条件

- 同じペアに同じ対象、依頼、選択範囲、条件、許可資料、推論一回あたりの制限を使う。A〜Dでは、比較構成の定義に従って条件または元の依頼をモデルに渡す。ルートとモデルはペア間で統一する。
- 最終評価はコードで判断できる回帰、条件に依存する回帰、正常変更を各6件とする。回帰・正常の双方で訂正と撤回を検証し、複数ファイルの差分を含める。
- 深度の再計測には前回と同じ6ケースを使う。6〜10件の許可資料の中に現行・旧版・隣接機能の資料を混ぜている。配信先では有効カタログから配信先を辿り、設定が公開であるという仮説が現行定義で支持・反証される。タイムアウトでも現行の解決処理と設定が仮説を支持・反証する。
- 未確認や失敗を検出率の分母に残す。正しい指摘が残った試行を検出に数え、完了できたかも別に記録する。同一ケースの3回中2回以上の検出をケース単位の判定に用いる。
- 実時間は推論全段階を含む。トークンはAPIが返す入出力の合計を使い、使用量の欠測を報告する。各構成の時間とトークンを同じペアで比較する。

## 実行前に決める許容値

この試験の暫定値。過去の深度比較の実測と、短い固定資料の運用を前提に余裕を持たせた。

| 指標 | Quick（A〜Dおよび資料先渡し） | Standard |
| --- | ---: | ---: |
| 正常ケースへの誤指摘 | 0件 | 0件 |
| 時間の中央値 / p95 | 20秒 / 35秒以下 | 35秒 / 60秒以下 |
| 1試行の入出力トークン合計の中央値 | 4,000以下 | 8,000以下 |

条件ありの採用判断は、同一ケースで条件依存の回帰の検出が複数改善し、重大な見落とし、正常例の誤指摘、失敗・未確認が増えないことを基準にする。深度の判断では、Standardでのみ検出できた不具合と、解消または正しく保留した未確認事項を確認する。時間・トークンが増えた場合は、その品質改善と照らし合わせる。使用量・品質・完了状態のいずれも、期待との差をそのまま記録する。
