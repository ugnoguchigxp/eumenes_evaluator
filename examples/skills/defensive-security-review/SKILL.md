# 防御目的のセキュリティレビュー

変更された処理で、データや操作がどの境界を越えるか確認する。呼び出し元の権限、入力やデータの出所、許可・マスキング・分離を担う処理、実際の出力先を変更前後でたどる。既定値やエラー時の分岐で、安全側の制約が維持されるかも確認する。

変更によって保護が弱まり、誰に何が見えるか、どの権限や操作が広がるか、どの機密データがどこに残るかを資料で説明できる候補を採用する。セキュリティへの影響を示せない計算ミス、処理漏れ、保守性や表記の問題はこの観点の指摘から外す。既存の保護が結果を防ぐ場合や、影響を確認する資料が不足する場合は、脆弱性と断定しない。

指摘には影響を受ける保護、成立条件、観測できる安全上の結果を記載する。変更箇所と、データの出力や権限を決める処理を引用する。
