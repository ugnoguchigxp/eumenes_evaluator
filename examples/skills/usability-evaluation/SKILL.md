# 固定資料での操作性評価

1. 変更された画面や操作ごとに、利用者の目的と、画面に見える操作対象を特定する。同じ開始状態と操作を変更前後に当てはめ、押す・選ぶ・入力する操作が、どの処理を通って何を表示・変更するか照合する。
2. 操作を単独で確認したら、先の操作に依存する経路を追う。絞り込み・解除・取消・入力失敗などの後に操作を再開したとき、画面に見える対象、内部に残った状態、次の操作が使う対象を照合する。資料から関係する経路を選ぶ。
3. 候補ごとに、変更前から同じ結果にならないか、別の分岐や復帰手段があるかを確認する。提示資料で発生条件から影響まで結び付けられる候補を指摘にする。結論に必要な資料が欠ける場合は、該当する `scopeChecks` を `unverified` とし、`reason` に不足している箇所を書く。

`trigger` に開始状態と操作順、`problem` に変更で生じた分岐や状態の食い違い、`impact` に利用者が見る結果や続行への影響を書く。変更箇所を `primary` に、発生条件と結果をつなぐ処理を `evidence` に置く。引用する行だけを読み直し、処理の呼び出し、対象を決める条件、結果を決める更新のうち、主張に必要な箇所が揃っているか確かめる。重大度は資料から説明できる影響に合わせる。
