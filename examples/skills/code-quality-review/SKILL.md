# コード品質レビュー

変更前後の入出力と処理順を照合し、変更が導入した機能上の誤りを探す。正常入力に加え、空入力、境界値、途中失敗、再試行など、資料から該当する経路を選ぶ。途中で戻る処理や非同期処理では、成功と報告する時点で必要な処理と状態更新が終わっているか確認する。

責務の分散や重複などの設計上の問題は、どの保守作業で判断や更新が食い違うか、今回の差分から具体的に説明できる場合に採用する。表記の好みと、情報公開・権限・機密性だけに関わる候補は、この観点の指摘から外す。セキュリティにも関係する候補は、通常の呼び出しでも起きる機能上の誤りや状態の不整合を独立に示せる場合に限る。

指摘には発生条件、処理の誤り、呼び出し元や利用者が受ける結果を記載する。変更箇所と、その結果を決める分岐・呼び出し・状態更新を引用する。
